# 可复核的实证记录

新增依赖快照和有限终审修订后的调度对照见 [2026-11-10 流程研究](workflow-study.md)。本页 24 题属于此前版本，不能直接用于评价新增架构。

本目录保存一批已完成的真实模型运行：预选的 24 道长文候选题全部保留，包括质量下降和未通过篇幅检查的题。`extension-evidence.json` 包含原题、评分标准、抽样记录、整篇与自适应输出、分块计划、审核意见、调用用量、逐项评分理由和历史汇总。它由本地原始产物 `data/writingbench/adaptive-extension-2026-10-31/` 冻结导出。

在仓库根目录运行，无需密钥或下载数据：

```powershell
python -m tools.verify_evidence
```

检查器验证预选题是否齐全、五项评分的均值、复用评分时两份输出是否完全一致，再从正文重新计算篇幅并核对逐题与全批结果。它验证记录内部的一致性，不能认证模型评分正确，也不能独立证明历史调用确实来自声明的模型。

| 观察 | 整篇生成 | 自适应策略 |
| --- | ---: | ---: |
| 本地 GLM 评分均值 /10 | 6.750 | 7.242 |
| 满足可解析的整篇篇幅条件 | 11/22 | 16/22 |
| 平均记录耗时 | 63.975 秒 | 170.696 秒 |

自适应策略先生成整篇，发现长文未达要求时尝试分块，再按篇幅距离选择稿件。24 题中 13 题触发并选用了分块稿，11 题复用整篇稿；最终 19 题 `completed`，5 题 `needs_review`。未变化的输出复用同一评分，避免把重复评分的波动算作改进。

这体现了一个具体收益：在这批任务里，分块补救使更多长文达到数值篇幅要求。代价也明确：额外生成和审核明显增加耗时，篇幅改善不能保证内容改善。例如第 969 题评分下降 2.0/10，两稿都未达到下限；第 259、276 题也出现评分下降。长度选择规则有可能选中内容更差的稿件。

本批使用 `qwen3.8-flash` 规划、`deepseek-v4.1-flash` 写作、`glm-5.2` 审核与评分。评分是本地探索性评估，非官方排行榜分数；没有独立人工盲评。样本面向长文候选，不能外推至所有写作任务。曾发生连接故障并重试，表中只计成功调用耗时，不能当作包含故障恢复的用户等待时间。`completed` 也不代表事实正确或用户满意。

历史综合分及 bootstrap 数值在数据中保留供核对。综合分使用人为选定的 80% 质量与 20% 篇幅权重，因此本页分别展示质量、合规和时间。架构的队列设计、预算解析和自适应选择共同参与了实验，现有结果不能把收益单独归因于双队列。

历史上的固定路由还出现过留出批次平均评分下降，背景和第二评审模型的分歧见 [诊断记录](../docs/writingbench-diagnosis-2026-10-31.md)。后续可用同一输入重新生成，但随机采样与端点变化会导致输出不同。需要重跑时使用 `tools.fetch_writingbench`、`tools.run_writingbench` 和 `tools.rescore_writingbench`；调用参数见 [WritingBench 方法](../docs/writingbench.md)。
