# 调度与结果完整性的最小实证研究（2026-11-10）

问题：在相同输入、块计划、写作器、审核器和最终要求下，写审重叠能否节省等待？跨块最终检查发现遗漏时，有限局部修订能否补齐？这两者分别验证，保留没有收益和无法修复的案例。

## 实现

- 写作与块审共享同一份依赖快照：正文、版本、审核状态、未解决意见及传递的不确定性。快照随检查点保存；默认仍允许使用待审草稿，但下游能看到其状态。
- 终审返回 `Issue.block_ids` 定位需修改的块。引擎将意见回传给目标块，失效并重做其依赖下游，复用其他块；然后重新合并并终审。默认最多一轮，每次调用可配置。无法定位或包含未知 ID 时保留意见，不自动扩大修改范围。
- `Policy.scheduling` 提供串行对照与双队列两种调度。审核规则、工作者数、重写上限和最终检查保持相同。
- 修订仍失败时返回 `needs_review`；严格模式返回 `blocked`。修订遇到执行错误时保留上一轮整篇草稿并报告错误，不把旧稿冒充修订成功。

## 受控实验：明确机制与失败边界

同一三块维护通知，写作和审核每次各模拟等待 0.03 秒。每种条件重复三次，串行与双队列的先后顺序交替；另设关闭最终修订的双队列对照。最终检查要求三条输入事实原样出现，独立于块审。块审故意只检查非空，遗漏与无法修复的行为也是预设的故障注入。

| 条件 | 串行中位耗时 | 双队列中位耗时 | 双队列关闭终审修订 | 指定事实完整性 |
| --- | ---: | ---: | ---: | --- |
| 独立块 | 0.1843 s | 0.1245 s | 0.1232 s | 三种路径均 3/3 次完整 |
| 完整依赖链 | 0.1873 s | 0.1847 s | 0.1861 s | 三种路径均 3/3 次完整，几乎无加速空间 |
| 初稿遗漏一条事实 | 0.2463 s | 0.1867 s | 0.1230 s | 有修订均 3/3 次完整；关闭修订为 0/3 |
| 写作器始终遗漏 | 0.2471 s | 0.1859 s | 0.1244 s | 三种路径均 0/3，保留 `needs_review` |

遗漏可修复时多做一次块写作、一次块审和一次终审，达到有限补救的目的；不可修复时这些工作增加了耗时，却没有改善结果。关闭修订最快的失败输出不能计为更快完成任务。依赖链还说明：为了稳定上下文而增加依赖，会直接减少可重叠的工作。

完整的 36 次运行、输出、事件、版本、调用计数和策略保存在 [workflow-controlled.json](workflow-controlled.json)。以上数字来自模拟延迟，不代表模型服务速度。

## 真实模型：相同任务的调度对照

使用已有端点，写作为 `deepseek-v4.1-flash`，块审为 `glm-5.2`，请求关闭思考模式，温度由适配器固定为 0.1。三条事实分别成块，每块要求一句中文且原样包含分配事实；两种依赖结构各重复两次，调度顺序交替。最终事实检查由本地规则执行，两条路径都启用同一检查和一轮修订预算。总调用预算 48 次；每次 HTTP 请求超时 60 秒。

| 计划 | 串行两次耗时 | 双队列两次耗时 | 中位数：串行 → 双队列 | 事实检查 |
| --- | --- | --- | --- | --- |
| 三个独立块 | 6.490、5.646 s | 5.097、3.808 s | 6.068 → 4.452 s | 两边均 2/2 完整 |
| 三块依赖链 | 5.083、5.373 s | 5.497、4.904 s | 5.228 → 5.200 s | 两边均 2/2 完整 |

八次均 `completed`，各执行三次写作、三次块审，没有局部或整篇重写，共 48 次调用，无调用故障。逐份查看输出，均为三个简短事实句，仅首份多了“本次”字样。完整输出和用量见 [workflow-live.json](workflow-live.json)。

独立块的两次配对均观测到较短墙钟时间；依赖链一次双队列较慢、一次较快，整体几乎持平。样本过少且服务延迟、生成文字不完全相同，不能把中位数差异当成稳定的加速保证。本轮没有单独保存 HTTP 重叠区间，因此不对墙钟差异作精确归因。依赖链是刻意设置的调度边界，不代表任务本身必须串行。

这个真实任务很小，最终确定性检查只证明指定事实出现，块审没有提出意见。它不覆盖长文篇幅、复杂格式、隐含矛盾或事实真实性；也未在真实模型中触发终审修订，因此不能宣称修订已经普遍提高真实文稿质量。较复杂写作任务中已有的质量下降与额外耗时仍保留在 [24 题历史研究](README.md)，该批使用旧流程，不能当作本轮架构的效果。

## 复现

离线重新汇总保存的结果，不调用模型：

```powershell
python -m tools.study_workflow --summarize research/workflow-controlled.json
python -m tools.study_workflow --summarize research/workflow-live.json
```

重新运行受控实验或在线实验（在线运行会调用已配置端点并消耗额度；建议写入新文件，保留原记录）：

```powershell
python -m tools.study_workflow --output data/workflow-controlled-new.json
python -m tools.study_workflow --live --repeats 2 --output data/workflow-live-new.json
```

当前结果支持：保留块审和最终检查时，独立工作仍可重叠；有限修订能修复预设遗漏，也可能付出成本后仍失败。需要继续验证的是复杂文稿上的错误定位是否可靠、修订是否引入新问题，以及这些额外调用是否抵消调度收益。
